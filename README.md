# Telegram Ads Platform — بسته مستندات شروع پروژه

این پوشه شامل مستندات کاملی است که برای شروع پیاده‌سازی این پروژه با **Claude Code** آماده شده. کد واقعی هنوز نوشته نشده — این بسته «بریف فنی + پرامپت عملیاتی» است.

## فایل‌ها

| فایل | محتوا |
|---|---|
| `CLAUDE.md` | دستورالعمل رفتاری Claude Code — نحوه‌ی کار مرحله‌به‌مرحله، چک‌لیست، کِی سوال بپرسه |
| `docs/PRD.md` | مشخصات کامل محصول (چه چیزی باید ساخته بشه) |
| `docs/ARCHITECTURE.md` | استک فنی، ساختار مانوریپو، اسکیمای دیتابیس، طراحی API |
| `docs/ROADMAP.md` | نقشه راه فاز‌به‌فاز با چک‌باکس — منبع اصلی پیگیری پیشرفت |

## چطور شروع کنم؟

1. این پوشه رو به یک ریپازیتوری خالی در GitHub push کن (یا از Claude Code بخواه این کار رو انجام بده).
2. پوشه رو در VS Code باز کن، Claude Code رو فعال کن.
3. اولین پیام به Claude Code:
   > `CLAUDE.md` رو بخون و طبق اون فاز ۰ از `docs/ROADMAP.md` رو شروع کن.
4. بعد از هر پاسخ، Claude Code باید وضعیت چک‌لیست رو نشون بده. اگر ندید، صراحتاً یادآوری کن که طبق `CLAUDE.md` گزارش تیک‌دار بده.
5. هر جا Claude Code سوالی پرسید (مخصوصاً درباره‌ی درگاه پرداخت واقعی، دامنه، یا سرور) پاسخ بده تا متوقف نشه.

## نکات مهم قبل از شروع واقعی (باید قبل از فاز ۸ آماده باشه)

- توکن ربات تلگرام (از @BotFather)
- یک دامنه (برای HTTPS مورد نیاز Telegram WebApp و webhook)
- دسترسی به یک VPS (طبق تصمیم، برای دیپلوی)
- credentials درگاه پرداخت ریالی (IDPay/NextPay) وقتی به فاز ۸ رسیدیم
- برای تست کریپتو: یک آدرس/کیف‌پول TRON تستی

هیچ‌کدوم از این‌ها الان لازم نیست — فقط بدون فراهم بودنشون، فازهای ۲ به بعد (ربات) و ۸ (پرداخت واقعی) گیر می‌کنه.

## راه‌اندازی محیط توسعه (Dev Setup) — از فاز ۰ به بعد

پیش‌نیازها: Node.js 20+، pnpm 9+، Docker.

```bash
# نصب وابستگی‌ها
pnpm install

# بالا آوردن Postgres و Redis برای محیط dev
docker compose up -d

# کپی کردن فایل env نمونه و پر کردن مقادیر واقعی
cp .env.example .env

# اجرای lint / typecheck روی کل مانوریپو
pnpm run lint
pnpm run typecheck
pnpm run format:check
```

ساختار مانوریپو (`apps/*`, `packages/*`) و توضیح هر بخش در `docs/ARCHITECTURE.md` بخش ۲ اومده. تصمیم‌های فنی گرفته‌شده در طول پیاده‌سازی (فراتر از چیزی که در ARCHITECTURE.md مشخص شده بود) در `docs/DECISIONS.md` ثبت می‌شن.

وضعیت پیشرفت پروژه فاز‌به‌فاز در `docs/ROADMAP.md` به‌صورت چک‌لیست زنده نگه‌داری می‌شه.
