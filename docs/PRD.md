# PRD — مشخصات محصول: پلتفرم تبلیغات تلگرام

## ۱. خلاصه

یک پلتفرم self-service تبلیغات برای اکوسیستم تلگرام. دو نقش اصلی کاربر:

- **تبلیغ‌دهنده (Advertiser):** کسب‌وکاری که می‌خواد در کانال‌ها، ربات‌ها یا نتایج جستجوی تلگرام دیده بشه.
- **ناشر (Publisher):** صاحب کانال یا رباتی که فضای تبلیغاتی خودش رو در اختیار پلتفرم می‌ذاره و پورسانت می‌گیره.

نقش سوم: **ادمین پلتفرم** که تبلیغ‌ها رو تأیید/رد می‌کنه، تراکنش‌ها رو رصد می‌کنه و تنظیمات کلی رو مدیریت می‌کنه.

تعامل کاربر عمدتاً از طریق **ربات تلگرام + Mini App (Telegram Web App)** انجام می‌شه؛ بدون نیاز به مرورگر جدا.

## ۲. جریان‌های کاربری (User Flows) — استخراج‌شده از نمونه‌ی مرجع

### ۲.۱ ورود اولیه (Onboarding)
- کاربر `/start` می‌زنه.
- ربات پیام خوش‌آمد + دکمه‌های اصلی رو نشون می‌ده: «اجرای اپلیکیشن»، «کانال»، «کامیونیتی»، «تغییر زبان».
- انتخاب زبان: 🇬🇧 English / 🇮🇷 فارسی / 🇸🇦 العربية (حداقل این سه، معماری باید i18n-ready باشه برای افزودن زبان بیشتر بدون تغییر کد).
- انتخاب زبان باید در پروفایل کاربر ذخیره بشه و در تمام پیام‌های بعدی ربات و Mini App اعمال بشه.

### ۲.۲ Dashboard (صفحه اصلی Mini App)
- خوش‌آمدگویی + سه تب پایین: **تبلیغ‌ها | داشبورد | پروفایل**.
- اگر کاربر هیچ تبلیغی نداره: حالت خالی («هنوز تبلیغی ندارید» + دکمه «یکی بسازید» + دکمه «شارژ حساب»).
- اگر تبلیغ داره: آمار کلی (کل بازدیدها، کل کلیک‌ها)، آمار دیروز (کلیک/بازدید دیروز)، لیست آخرین پرداخت‌ها/برداشت‌ها.
- بالای صفحه: موجودی سکه‌ی کاربر (آیکن سکه + عدد) — همیشه قابل مشاهده.

### ۲.۳ ساخت تبلیغ جدید (مهم‌ترین فلو — Wizard چند مرحله‌ای)

**مرحله ۱ — هدف‌گیری مخاطب (Ad Placement Type):**
انتخاب یکی از: `کانال‌ها` | `ربات‌ها` | `جستجو (نتایج سرچ تلگرام)` | `کاربران`.

**مرحله ۲ — عنوان تبلیغ:**
فیلد متنی ساده، اجباری.

**مرحله ۳ — هدف‌گیری تفصیلی (Targeting) — همه اختیاری مگر خلاف اون گفته بشه:**
- زبان کانال‌های هدف (چندانتخابی از لیست زبان‌ها)
- دسته‌بندی‌های هدف (چندانتخابی از تاکسونومی دسته‌بندی از پیش تعریف‌شده — مثل: تکنولوژی، سرگرمی، اخبار، کریپتو، آموزش...)
- کانال‌های هدف خاص (وارد کردن یوزرنیم یا لینک t.me؛ چندتایی؛ auto-suggest کانال‌های مشابه بعد از افزودن اولین مورد)
- دسته‌بندی‌های مستثنا (Exclude)
- کانال‌های خاص مستثنا (Exclude)
- کشورهای محدودشده به‌صورت خودکار اعمال می‌شه (طبق تحریم‌ها/قوانین سرویس پرداخت — قابل‌تنظیم در پنل ادمین، پیش‌فرض چند کشور نمونه)

**مرحله ۴ — محتوای تبلیغ (Creative):**
- متن تبلیغ (پشتیبانی از Markdown محدود — می‌تونه از طریق یک ابزار کمکی/دستور جدا فرمت‌دهی پیشرفته اضافه کنه)
- آدرس URL مقصد (لینک کانال، پست، یا ربات هدف)
- سوییچ «نمایش عکس پروفایل در آگهی»
- آپلود عکس یا ویدیوی تبلیغ (اختیاری)
- **پیش‌نمایش زنده (Live Preview)** دقیقاً به شکلی که در تلگرام دیده می‌شه (کارت Ad با دکمه «مشاهده» / View و گزینه Mute)

**مرحله ۵ — بودجه و نرخ:**
- وضعیت اولیه: `فعال` (بعد از تأیید ادمین بلافاصله شروع می‌شه) یا `تعلیق` (بعد از تأیید در حالت مکث می‌مونه تا کاربر دستی فعال کنه)
- محدودیت بازدید روزانه برای هر کاربر (گزینه‌های ثابت مثلاً ۱ تا ۴ بار — جلوگیری از آزاردهنده شدن تبلیغ برای یک کاربر)
- بودجه‌ی اولیه (با دکمه‌های درصدی کمکی ۲۵٪/۵۰٪/۷۵٪/۱۰۰٪ نسبت به موجودی کاربر)
- **CPM (هزینه به ازای هزار نمایش)** قابل تنظیم دستی توسط تبلیغ‌دهنده؛ توضیح داده بشه که CPM بالاتر = اولویت نمایش بالاتر و سرعت جذب بازدید بیشتر (این یک مزایده‌ی داخلی real-time بین تبلیغ‌های فعال است)
- پذیرش قوانین استفاده از پلتفرم (چک‌باکس اجباری + لینک به صفحه قوانین)
- دکمه نهایی «ایجاد تبلیغ» (غیرفعال تا وقتی چک‌باکس قوانین تیک نخورده)

**اعتبارسنجی موجودی:** اگر موجودی کاربر برای حداقل بودجه‌ی لازم کافی نباشه، پیام هشدار + لینک مستقیم «افزایش موجودی» نشون داده بشه و دکمه ساخت تبلیغ غیرفعال باشه.

### ۲.۴ کیف پول / افزایش اعتبار
- ورودی مقدار «سکه» (Coin) به‌صورت دستی یا دکمه‌های سریع (۲۰,۰۰۰ / ۵۰,۰۰۰ / ۱۰۰,۰۰۰ / ۳۰۰,۰۰۰)
- روش پرداخت: **پرداخت ریالی** (درگاه IDPay/NextPay یا مشابه ایرانی)، **استار تلگرام (Telegram Stars / XTR)**، **کریپتو ترون (USDT TRC-20)**
- بعد از تکمیل پرداخت، سکه فوراً (پرداخت ریالی/استار) یا پس از N تأیید بلاک‌چین (کریپتو) به کیف پول کاربر اضافه بشه؛ webhook/polling برای هر سه روش پیاده بشه.
- تاریخچه‌ی کامل تراکنش‌های کیف پول (واریز و برداشت) قابل مشاهده باشه.

### ۲.۵ لیست تبلیغ‌های من (My Ads)
- لیست تبلیغ‌ها با وضعیت (در انتظار تأیید / فعال / تعلیق‌شده / رد شده / پایان بودجه)
- امکان ویرایش، توقف موقت، افزایش بودجه، حذف
- آمار جزئی هر تبلیغ (نمایش، کلیک، CTR، هزینه‌ی تاکنون خرج‌شده)

### ۲.۶ سمت ناشر (Publisher) — این بخش در اسکرین‌شات‌ها مستقیم دیده نشده ولی برای کارکرد کامل پلتفرم ضروریه؛ باید طراحی و اضافه بشه:
- ثبت کانال/ربات به‌عنوان فضای تبلیغاتی (نیاز به اثبات مالکیت: افزودن ربات پلتفرم به‌عنوان ادمین کانال، یا کد تأیید در بیو ربات)
- انتخاب دسته‌بندی کانال/ربات (برای matching با targeting تبلیغ‌دهنده‌ها)
- تنظیم حداقل CPM قابل‌قبول برای نمایش تبلیغ در کانال/ربات خودش
- گزارش درآمد و درخواست برداشت (Payout) با همون سه روش پرداخت (ریالی/استار/کریپتو) به‌صورت معکوس
- SDK/راهنمای فنی برای embed کردن تبلیغ:
  - در کانال: از طریق ربات پلتفرم که به‌صورت زمان‌بندی‌شده پست تبلیغاتی در کانال منتشر می‌کنه (با API چک‌کردن مجوز ادمین)
  - در ربات: از طریق یک SDK کوچک (npm package یا REST endpoint ساده) که صاحب ربات با یک تابع/endpoint تبلیغ مناسب رو fetch و در پیام inject می‌کنه

### ۲.۷ پنل ادمین
- صف تأیید تبلیغ‌های جدید (Moderation Queue) با امکان تأیید/رد + دلیل رد
- مدیریت دسته‌بندی‌ها (categories taxonomy)
- مدیریت کاربران (مسدودسازی، مشاهده تراکنش‌ها)
- مدیریت درخواست‌های برداشت ناشران (تأیید/رد payout)
- تنظیمات کلی: نرخ تبدیل سکه به تومان، حداقل/حداکثر CPM، درصد کمیسیون پلتفرم از گردش تبلیغاتی، لیست کشورهای محدود
- گزارش‌ها و داشبورد آماری کلی پلتفرم (درآمد، تعداد تبلیغ فعال، تعداد ناشر فعال)
- audit log کامل اقدامات ادمین‌ها

## ۳. الزامات غیرعملکردی (Non-Functional Requirements)

- **چندزبانگی:** حداقل fa/en/ar از ابتدا با ساختار i18n قابل توسعه.
- **امنیت مالی:** تمام محاسبات مالی سمت سرور؛ idempotency روی پرداخت‌ها؛ audit log.
- **مقیاس‌پذیری:** موتور نمایش تبلیغ (ad serving) باید بتونه با حجم بالای درخواست (هزاران impression در دقیقه در آینده) کار کنه؛ از Redis برای cache و rate limit و صف پیام (BullMQ) برای پردازش async استفاده بشه.
- **ضدتقلب (Anti-fraud):** جلوگیری از self-click، کلیک‌های تکراری مشکوک از یک IP/کاربر، بازدید ربات‌گونه.
- **قابلیت مشاهده (Observability):** لاگ ساختاریافته، متریک پایه (Prometheus-ready)، هشدار خطا.
- **قابلیت نگهداری:** کد ماژولار، مستند، تست‌دار طبق CLAUDE.md.

## ۴. محدوده فاز اول (MVP) در برابر فازهای بعدی

فاز اول (MVP) باید شامل باشه: ثبت‌نام از طریق ربات، ساخت تبلیغ کامل (بدون بخش جستجو/کاربران — فقط targeting کانال/ربات)، کیف پول با حداقل یک روش پرداخت (Stars چون ساده‌ترین API رسمی تلگرامه)، موتور نمایش ساده روی کانال‌های تستی، پنل ادمین ابتدایی برای تأیید تبلیغ. باقی موارد (کریپتو، ریالی، targeting جستجو/کاربران، SDK کامل ناشر) در فازهای بعدی — دقیقاً طبق `docs/ROADMAP.md`.
